01The Concept

一条专利记录，为什么不够？

搜索引擎能匹配“液冷”“温差”等关键词，却未必知道：哪些文献属于同一申请、两条方案是否解决同一个技术问题、宣称的效果由哪个原文片段支持。Ontology 的工作是把这些问题转成明确的类型与关系。

Without Ontology / 字符串检索

文献是一组扁平字段

一篇摘要写“微通道冷板降低热点”，另一篇写“均热板改善温差”。系统可能只看到两个互不相同的文本。

title = "Battery cooling..."
abstract = "Fluid channels reduce hot spots..."
keywords = ["thermal", "battery"]

能找到关键词，但要回答“同一问题有哪些不同解决方案”，还得推断隐藏在句子里的语义。

With Ontology / 语义检索

文献成为一张可遍历的图

从文献抽取技术问题、具体方案、用到的概念、报告的效果，再连接回证据来源。

Publication → disclosesSolution → Solution
Solution → addressesProblem → Problem
Solution → producesEffect → Effect

同一问题的不同解决方案会因为指向同一个 Problem 对象而被关联。

—虚构公开文献
—申请记录
—技术方案／证据链
—归一化技术问题
ⓘ
演示数据声明：所有专利号、企业、文献标题、效果百分比、摘要证据均为人为编造，用来演示图谱和查询逻辑。效果数值不能用于真实技术评估，置信度表示示例中的抽取置信程度，不代表效果已经得到实验验证。
Schema 层

定义世界：Publication、Solution、Problem、Effect 等 Class 与关系类型；由 RDF / RDFS / OWL 表达。

Instance 层

描述事实：某篇虚构公开文献披露某个方案、某个摘要片段支持某项声称。

Constraint 层

检查完整性：每个方案必须关联至少一个问题、一种技术概念和一个效果；由 SHACL 验证。

Execution 层

检索与应用：全文/向量检索负责候选召回，结构化数据/RDF 图谱负责路径查询和去重。Ontology 并非查询引擎。

04Problem → Solution → Effect

从“查专利”升级到“比较技术路线”

这里是本次扩展的核心。多个专利可以使用不同技术解决同一个问题。你选择一个问题，再选择不同公开文献，系统展示它们各自的方案、相关概念、声称的效果及其证据。

⚑
效果对比不等于优劣排名。例如“最高温度下降 18%”与“温差下降 22%”的评价指标不同；即使指标相同，测试边界条件也可能不同。Ontology 的价值是把技术主张与来源关联起来，而非自动证明其真实性。
05Formal Semantics

RDF、OWL、SHACL 如何协同？

同一事实可以有不同层次：OWL 描述关系“应该是什么意思”，RDF 记录具体的关系实例，SHACL 检查缺项，SPARQL 找出符合关系路径的数据。切换下面的标签来理解它们各自负责什么。

patent_ontology.ttl
RDF

事实是三元组

“文献 A 披露了方案 B”并不只是数据库外键，也是可交换的 Subject–Predicate–Object 关系。

OWL / RDFS

关系有正式语义

`disclosesSolution` 的 domain 是 PatentPublication，range 是 TechnicalSolution。OWL/RDFS 主要用于表达和推理，不是拒绝非法数据的校验器。

SHACL

数据有完整性门槛

方案没有连接问题、概念或效果时可生成违反约束的报告；证据缺乏来源文献时亦可被发现。

07Production Architecture

研究型 Ontology 如何进入真实检索平台

Playground 类的建模 UI 可以编辑 Schema，但真正的专利智能检索还需要资料接入、标准化映射、实体对齐、约束校验、索引和查询执行。下方是一个适合 FastAPI / TypeScript 技术栈的落地思路。

01

数据接入 / 抽取

专利数据源、OCR、文本切片；生成带出处的原始文档记录。

→
02

Ontology + Validation

实体解析、概念归一、问题—方案—效果抽取；OWL / SHACL 与人工审核。

→
03

检索 / Agent

PostgreSQL + 向量/全文索引 + 图关系存储；受控查询、证据与报告。

Recommended Separation

Schema 与 Instance 分离管理

Ontology 文件建模稳定的概念和属性，专利文献及抽取结果作为版本化数据；技术断言保留支持它的文本证据。不要每增加一篇专利就修改 OWL Class。

Important Boundary

Ontology ≠ 实际执行引擎

Ontology 提供规范语义；全文召回、相似度计算、专利族算法、法律状态解析与外部 Action 均需要专门运行组件。RDF 可以是交换标准，而不是所有业务数据的唯一数据库。
