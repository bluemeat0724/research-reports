为什么需要内外两层 while？

内层持续处理工具续轮和 steering；内层自然结束后，外层再尝试 follow-up。finishTurn 的 continue 决策还可保证一次 context-only 请求。L178–320 ↗

为什么 tool_execution_end 不等于结果入历史？

parallel 先按各工具实际完成时点发 end；Promise.all 后，再按 assistant 中的工具调用顺序发 toolResult 消息。UI 完成顺序与 transcript 顺序可以不同。L586–659 ↗

05

读懂这些例外，才算读懂循环

先给自己一个判断，再展开答案。所有结论仅针对本页固定源码版本。

工具返回 isError，就会结束整个 run 吗？

不一定。工具错误可以成为 toolResult 返回给模型，循环继续。模型响应自身的 stopReason="error" / "aborted" 才走硬退出分支。
L245–278 ↗

一个工具 terminate=true，整批就终止吗？

不是“任意一个”。shouldTerminateToolBatch 要求批次非空，且每个 finalized result 都设置 terminate=true；它关闭工具触发的续轮，后续仍有 finishTurn 与队列决策。
L690–692 ↗ · L267–314 ↗

输出被 token limit 截断，参数还能跑吗？

如果 assistant stopReason="length" 且包含工具调用，本批次全部转换为错误结果，不执行这些工具。看似通过 JSON 解析的参数也可能不完整。
L263–270 ↗ · L471–502 ↗

收到 agent_end 就一定 idle 了吗？

Agent.subscribe 的异步监听器仍可能在运行。Agent 要等 agent_end 监听器完成后才在 finishRun 清理 isStreaming、pendingToolCalls 并 resolve waitForIdle。
L507–612 ↗

prepareNextTurn 会在首轮运行吗？

不会。它依赖 lastCompletedTurn，只在已经完成一轮且确定进入下一轮时执行。prepareRequest 则在每次请求前运行，包括首轮。
L184–242 ↗

直接抛错与流内 error 是一样的吗？

不是。StreamFn 与部分低层回调约定不抛错，应通过协议表示失败。Agent 类有额外 catch 和合成失败事件；不要假设低层 agentLoop 自动提供同样兜底。
