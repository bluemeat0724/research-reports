g-loop 两种运行方式对比

点击「播放」，在同一时间线上模拟：用户发起一个长任务，执行到中途又发来一个新问题。

A. 现状：单 run 阻塞式

一个会话只有一个 run，fence 锁保证同一时间只有一个写者（store/pg.py:25-36）

B. 前台对话 loop 加后台 run

前台只负责回话和派活；长任务在子会话里跑，完成后通过事件把结果推回前台
A 的问题
  • run 执行期间用户发来的新消息只能排队，或者因为拿不到 fence 而被拒绝
  • 想插话只能取消（CancelToken），已经做完的部分也跟着中断
B 需要补的东西
  • 后台 run 有独立的 run_id 和子会话，可以挂起、恢复、取消
  • step 边界的收件箱（可选）：run 每个 step 开始前取出新消息
  • 完成事件：events/ 目前是空目录，需要推送机制
  • 前台只需要短 run，不需要改 fence 的语义
